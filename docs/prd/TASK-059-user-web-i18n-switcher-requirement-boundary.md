## 2. 目标和用户价值

本新增需求的目标是在用户端提供明确、稳定、可发现的多语言切换能力，并同步约束顶部菜单在不同语言文案长度下的间距、换行和响应式表现，避免英文、马来文或繁体中文切换后出现导航挤压、重叠、横向溢出、按钮变形或演示时页面观感失控。

对用户的价值是：国际学生、家长和运营演示人员可以在当前语言下浏览 StudyMY 的核心页面，不需要通过浏览器翻译或手动刷新来理解导航和主要操作；顶部菜单作为全站入口，在多语言状态下仍能稳定引导用户进入院校库、规划、收藏、对比、费用估算和智能推荐等核心流程。

对产品的价值是：多语言切换从“页面文案能力”升级为“可用的用户端入口和布局稳定性要求”，后续实现不只补一个语言下拉框，还必须证明长文案、窄屏、登录态、收藏数量和工具入口组合下不会造成样式变形。

## 3. 需求边界

本需求聚焦用户端多语言切换入口和顶部菜单在多语言下的视觉稳定性。当前代码中已经存在 i18n 配置和 `zh-CN`、`zh-TW`、`en`、`ms` 四类语言文案基础；后续实现应优先沿用项目已有语言列表，除非产品另行确认需要增减语言。

这里的“多语言切换功能”至少包含：

- 用户端全局可见的语言切换入口。
- 当前语言展示、可选语言名称和切换后的即时反馈。
- 切换后当前路由、登录状态、收藏状态、对比状态和页面筛选状态不应被无意重置。
- 当前语言选择应持久化，刷新页面后仍使用用户最近选择。
- 导航、按钮、弹窗入口、错误提示和核心页面标题不应出现缺失 key 或明显混合语言。

这里的“顶部菜单间隔放大”和“多语言下的样式变形”至少包含：

- 顶部导航菜单项之间的间距、最小宽度、换行策略和按钮尺寸需要适配英文长文案。
- 语言切换控件、登录按钮、会员入口、收藏数量角标和工具按钮不能互相遮挡。
- 桌面端不能因为英文菜单较长导致品牌区、导航区、右侧操作区重叠。
- 平板和移动端不能出现整页横向溢出、按钮文字挤压、语言选择器超出视口或菜单点击区域错位。
- 如果后续采用折叠菜单、更多菜单或响应式换行，需要保证交互清晰且不破坏静态页面视觉基线。

## 4. 功能范围

### 4.1 覆盖页面和控件

后续实现应只覆盖用户端与多语言切换和顶部菜单布局直接相关的范围：

- 用户端全局顶部导航，包括品牌区、导航链接、费用估算入口、智能推荐入口、收藏、对比、登录或会员入口。
- 用户端语言切换控件，包括当前语言展示、可选语言列表、键盘和触控可操作性。
- 切换语言后的全站基础状态同步，包括路由保持、当前页面重新渲染、持久化存储和刷新恢复。
- 与顶部菜单发生布局冲突的直接相邻元素，例如首屏 Hero 顶部、移动端头部区域、sticky header 或右侧操作区。
- 语言文案长度直接影响的导航标签、按钮标签、角标、tooltip、aria label 和表单提示。

### 4.2 后续实现应覆盖的体验点

- `zh-CN`、`zh-TW`、`en`、`ms` 四语言均能从用户端切换，并能在刷新后保留选择。
- 英文长文案下顶部菜单保持可读、可点、可聚焦，不出现文字截断后语义不可识别。
- 多语言切换后不出现缺失 key、硬编码混用、后端英文错误直出到中文界面，或中文动态数据直出到英文和马来文界面。
- 桌面端、1180px、900px、768px、760px、600px 和移动端宽度均无横向整页溢出、菜单重叠、按钮挤压和布局跳动。
- 登录态、未登录态、收藏数量存在和不存在时，顶部菜单都需要保持稳定。
- 后续实现如果触碰共享 i18n formatter、运行时文案清洗或全局 CSS，需要在技术方案中明确影响面和回归范围。

## 8. 后续实现验收口径

后续 TASK-060 和 TASK-061 实现时，至少需要满足以下验收口径：

## 12. 风险和后续实现边界

- 顶部菜单只简单增大 `gap` 可能在 1180px、900px 或移动端造成更严重的空间不足；后续实现需要结合 flex、wrap、min-width、overflow 和折叠策略验证。

- 语言切换控件如果仍使用原生 select，需要验证宽度、可访问名称、键盘操作和移动端样式；如果改为自定义菜单，需要额外验证 focus、Esc、点击外部关闭和屏幕阅读器语义。
- 当前项目仍有多语言动态数据和错误提示相关 Review 问题；后续实现不能因为新增切换入口而扩大混合语言问题。
- 当前工作区存在大量未提交改动，后续实现和提交需要严格区分 TASK-060、TASK-061 与历史改动，避免把无关文件混入验收和 commit。
