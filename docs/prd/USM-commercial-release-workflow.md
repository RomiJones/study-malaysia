# USM 商用发布固定工作流

## 目标

将 USM 本硕博数据从候选生成、费用语义、数据库状态、公开 API 到四语页面的商用标准固化为一个可重复、失败即阻断的发布门禁。

## 数据合同

- 本科、硕士、博士规范总数固定审计为 63、305、95。
- 公开国际生项目固定审计为 63、304、93，共 460。
- `needs-review` 必须为 0；3 条仅限马来西亚申请人的记录保留在审计层且不得公开。
- 主学费只接受官网直接公布、唯一对应项目或已选方向的标准项目总学费。
- 候选来源中，每学期费率继续使用 `official-rate-only`；进入数据库和公开 API 后，按官方全日制费率乘以官方最短全日制学期数，状态使用 `calculated-from-official-rate`。
- 费率型记录必须在公开 `tuitionDisplay` 中只展示一个标准总学费。计算公式、非全日制费率和排除项只在详情说明中展示，不得在列表重复展示。
- 只有官网没有任何可匹配数字费用时，用户端才显示“官方未公布”。
- 无数字的官方费用行使用 `official-total-unpublished`，不得标记为已匹配官方总额。
- 公开项目学费状态必须精确为：194 条 `matched-official`、213 条 `calculated-from-official-rate`、53 条 `not-published`。
- `calculated-from-official-rate` 必须有正数 `tuitionAmount` 和单一币种总额；`not-published` 的金额字段必须为 `null`，禁止用 `0` 表示未公布。
- 院校详情 API 必须保留 `tuitionInfo.note`，用于展示计算公式、官方学年、非全日制费率，以及延期学期和其他单独费用未计入的说明。
- 费用范围、模糊估算、延期或超期费用均不得进入主学费字段。
- 院校概览不得汇总不同专业的最低至最高费用。

## 生成与导入顺序

1. 从版本化官方来源重新生成硕士和博士候选，禁止手工修改生成 JSON。
2. 对当前官方详情页做字段完整性差异检测。USM 官网详情页的 HTML tab、accordion 和隐藏面板是专业级字段权威；Jina/Markdown 缓存缺字段时，不能直接判定“官方未公布”。
3. 对高风险字段逐项比对候选与当前官方详情页，包括开学月份、学制、入学要求、语言要求、课程结构、研究方向、实习/项目和费用说明。发现官网已有字段但候选缺失时，必须先修构建器再重生成候选。
4. 开学月份规则：研究型项目只有在专业详情页没有固定月份时才使用全年开放申请语义；如果详情页 `SEMESTER INTAKE` 明确写出月份，必须展示该月份。授课型、混合型、在线、临床项目同样优先使用详情页固定月份。
5. 运行候选专项验证与 `scripts/audit-official-total-tuition.py`。
6. 执行数据库 dry-run、备份和受控事务导入。
7. Master 与 PhD 导入不能并行；Master 导入后必须顺序重跑 PhD 导入，以恢复 USM profile 的 463/460 总汇总。
8. 运行本硕博数据库专项验证。
9. 检查公开 API 数量、状态分区、费用标量、开学月份结构化数组和非公开记录泄漏。
10. 运行全量测试、生产构建与四语审计。
11. 使用真实页面完成四语、硕士列表、博士列表、DBA 总学费、代表性专业详情页和浏览器控制台验收。
12. 更新中文开发记录；无 Notion 写入连接时明确记录真实 Notion 未更新。
13. 仅提交和部署已通过门禁的聚焦改动，不发布包含无关未提交文件的工作区。

## 当前详情页差异审计

- 每次遇到用户指出“官网页面有值但项目显示兜底文案”时，不能只修单点记录，必须扩展为同层级全量检测。
- 单个专业缺字段视为字段覆盖率事故，而不是孤立数据修补；必须按同层级、同字段、同页面结构、同采集来源批量排查，避免后续反复出现零散漏采。
- 先以官方详情页 URL 为单位抓取当前 HTML；直连失败时可使用只读文本代理补抓；传输失败只能记为 transport exception，不得当作官方未公布。
- 差异审计至少输出：检测记录数、当前官方有值的记录数、修复前差异数、修复后实质剩余差异数、仅顺序差异数、传输不可达数和代表性样本。
- 差异为字段集合顺序不同但值集合一致时，可归为 order-only；字段值缺失、状态错误或被 fallback 覆盖时必须修复。
- USM 硕士开学月份的参考产物为 `data/imports/usm/2026-06-16/master-level-audit/current_html_intake_fix_audit.json`。

## 全院校防返工原则

- 本工作流中的差异审计方法可迁移到所有院校采集任务；USM 只是当前案例，不应把规则写死为 USM 独有。
- 面对不同院校官网时，应先判断信息公布形态：静态 HTML、tab/accordion、JavaScript 渲染、PDF 招生手册、费用表、申请指南、学院子站或多页面联动，再选择对应采集策略。
- 缓存、Markdown reader、文本代理和搜索结果只作为传输或发现层；若这些层缺字段，必须回到当前官方页面或官方附件核验。
- 每次修复都优先修构建器、解析器、字段映射或导入器，并重新生成候选与审计报告；禁止只手改生成 JSON 来掩盖单条问题。
- 发布前必须有字段覆盖率视角：哪些字段全量已采、哪些官网确实未公布、哪些只是传输不可达、哪些需要人工复核。

## 最终门禁

API 与 Web 服务启动后运行：

```bash
node scripts/verify-usm-commercial-release.mjs
```

可显式指定地址和报告路径：

```bash
node scripts/verify-usm-commercial-release.mjs \
  --api-url http://127.0.0.1:3000/api/universities/universiti-sains-malaysia-usm \
  --web-url http://127.0.0.1:5173/universities/universiti-sains-malaysia-usm \
  --report tmp/reports/usm-commercial-release-gate.json
```

该命令依次执行候选审计、交付 envelope 审计、三层级数据库专项验证、总学费政策审计、全量测试、生产构建、四语审计、公开 API 和真实浏览器检查。任一检查失败即返回非零退出码，发布决策为 `blocked`。

## 回滚

- 每次受控写入使用导入器生成的 `apps/api/tmp/backups/` 备份。
- 数据回滚按对应导入器的备份恢复流程执行。
- 代码发布只使用通过门禁的聚焦提交；不得用 `git reset --hard` 或覆盖用户未提交工作。

## Notion

Notion 是中文任务与文档源，不是业务数据库。无可写连接器时更新本地中文任务快照，并明确记录真实 Notion 未更新。
