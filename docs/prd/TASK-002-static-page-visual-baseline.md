## 2. 结论摘要

静态 HTML 是用户端视觉和交互的最高优先级基准。后续用户端实现必须优先复用或等价实现静态页的 CSS token、字体、间距、卡片、筛选区、弹窗、按钮、表格、浮动按钮、响应式断点和动效，不得沿用旧系统当前偏米色/绿色、超大圆角和营销卡片化风格作为最终用户端样式。

静态 HTML 内联 CSS 提供了完整样式系统：18 个 `:root` 变量、约 402 个 CSS 选择器、5 个关键动画、10 条媒体查询声明。静态页经自身 `dedupeUniversities` 逻辑合并后包含 119 所院校、687 个专业，其中 `publicDisplayStatus = ready` 的可商用展示专业为 239 个，ready 专业层级分布为本科 74 个、硕士 136 个、博士 29 个。

旧系统已经具备 Vue 3 用户端、NestJS 后端、Element Plus 管理端和共享类型雏形，但当前用户端视觉系统、页面结构、字段完整度和专业状态模型均不足以直接 1:1 还原静态页。后续实现需要先把视觉 token 与组件基线固化，再由后端和管理端补齐可驱动这些界面的字段。

Notion 是中文项目文档和任务管理来源，不是业务数据库；运行时业务数据必须进入 MySQL/API/前端状态体系。

## 4. PRD 补充

### 4.1 产品目标

本任务后的用户端实现目标是：把静态 HTML 中已经验证的视觉体验沉淀为 Vue 用户端可复用的样式系统。后续任何用户端页面、弹窗、筛选器、卡片和表格实现，都必须以本视觉基线为验收依据。

### 4.2 用户体验原则

- 用户端首屏必须呈现静态页的深墨色品牌 Hero、金色强调、居中搜索和统计栏。
- 院校浏览必须保留静态页的左侧粘性筛选、右侧横向院校卡片、分页和活跃筛选标签。
- 院校详情必须保留深色详情 Hero、标签页、官方信息卡片和稳定专业表格。
- 专业详情必须以弹窗为主，不以独立页面替代静态页交互。
- 收藏、对比、规划、费用估算、智能推荐、登录和浮动按钮必须与静态页一致地在当前上下文中打开或切换。
- 移动端必须按静态页断点转换布局，不得只依赖桌面样式自然挤压。

### 4.3 非目标

- 本任务不实现 Vue 代码。
- 本任务不导入静态 HTML 数据。
- 本任务不扩展业务接口。
- 本任务不修改三端实现文件。
- 本任务不把 Notion 作为业务运行时数据库。

### 6.19 动效规则

- 全局常规过渡多为 `all .2s ease`。
- 卡片 hover 使用 `.25s cubic-bezier(.4,0,.2,1)` 或 `.3s cubic-bezier(.4,0,.2,1)`。
- 图片 hover 放大使用 `.5s ease`。
- Hero 元素使用 `fadeDown .6s`，按 `.1s` 到 `.4s` 延迟递进。
- 卡片入场使用 `fadeUp .45s cubic-bezier(.4,0,.2,1)`，每张卡片延迟 `.04s` 到 `.32s`。
- 弹窗遮罩使用 `fadeIn .25s ease`。
- 进度条宽度变化使用 `.6s ease`。
- 后续实现不得增加与静态页冲突的大幅动画、弹性动画或滚动视差。
