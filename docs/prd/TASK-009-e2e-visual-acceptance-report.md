## 8. 风险和建议

- **视觉风险**: 当前用户端与静态 HTML 差距较大，后续不应只做局部 CSS 调整，应按静态页组件结构系统性还原。
- **数据风险**: 静态页数据量大且字段丰富，后端必须先补齐字段契约和导入校验，再让用户端依赖 API 做完整渲染。本轮 API 返回 698 条专业记录，与静态 HTML 687 个专业基线不一致，且存在非专业标题进入专业列表的风险。
- **验收风险**: 构建通过不代表视觉通过；后续 UI 任务必须保留静态页与 Vue 页面同视口截图。
- **状态风险**: 收藏、对比、规划和申请任务涉及访客态与登录态合并，必须单独验收。
- **性能风险**: 管理端当前构建有大 chunk 警告，后续字段维护功能增加前应规划分包。
- **工具风险**: 当前目录不是 Git 仓库，无法按项目流程提交 commit；后续应确认真实 Git 工作区。
- **Notion 风险**: 真实 Notion 本轮未更新，后续应提供 `NOTION_PROJECT_HOME` 或 TASK-009 页面 URL，避免本地文档与真实 Notion 分叉。
