## 2. 结论摘要

静态 HTML 是用户端最终视觉和交互基准。旧系统已经具备 Vue 用户端、NestJS API、Element Plus 管理端和共享类型雏形，也已经覆盖首页、院校详情、专业详情、收藏、对比、规划、会员、登录、费用估算、推荐、后台学校/专业/申请/权限等基础模块，但当前系统与静态页之间仍存在三类核心差距。

第一，用户端视觉体系不一致。静态页使用深墨色、金色、纸色、青绿、红色、蓝色组成的克制品牌系统，并要求 16px/10px 圆角、DM Sans/DM Serif Display、深色 Hero、260px sticky 筛选栏、横向院校卡片、7 列专业 grid、桌面居中/移动贴底弹窗。旧系统仍是米色/绿色主视觉、32px 大圆角和营销卡片化页面，需要整体重构，而不是局部补样式。

第二，后端模型和接口不能完整驱动静态页。旧系统学校和专业实体以 CNY 年学费、基础语言/GPA、四语言展示为主，缺少 UM 官方数据需要的 RM 总学费、官方来源 URL、公开展示状态、核验状态、官方原文、申请周期、申请费用、官方材料、开学备注、认证备注、审计备注和不开放国际学生说明等字段。现有 API 也缺少混合搜索建议、筛选聚合、专业直达弹窗定位、对比服务端状态、静态数据导入校验等能力。

第三，管理端维护能力不足。旧系统有学校、专业、内容、申请、权限、菜单、配置、字典和日志管理，但学校/专业表单只覆盖旧模型字段，无法维护静态页要求的官方档案、官方来源、公开展示状态、官方学费来源、核验日期、审计备注和导入校验结果。后续必须先补后端数据契约和管理端字段维护，再做用户端 1:1 还原。

### 3.2 核心交互

- 院校、专业、城市混合搜索。
- 搜索建议浮层、命中高亮、回车搜索、Escape 关闭建议。
- 点击院校建议进入院校详情。
- 点击专业建议进入所属院校详情，并打开专业详情弹窗。
- 筛选项覆盖院校类型、学历层级、QS 排名、预算、专业类别和免语言开关。
- 筛选分组可折叠，活跃筛选可单项移除或全部清除。
- 筛选变化后分页回到第 1 页。
- 收藏院校、收藏专业、取消收藏。
- 添加/移除院校对比，最多 4 所。
- 申请规划基于学生画像生成推荐、材料清单、申请任务和签证步骤。
- 费用估算基于学费、生活费、学制和杂费计算。
- 智能推荐基于学历、类别、预算、GPA、IELTS 和免语言偏好生成匹配结果。
- 登录弹窗切换登录/注册，本地未登录状态与后续服务端持久化需要合并策略。

### 4.2 字体与排版

- 正文字体：`DM Sans`, `system-ui`, `sans-serif`。
- 标题字体：`DM Serif Display`, `Georgia`, `serif`。
- 页面基础字号：`15px`。
- 页面基础行高：`1.6`。
- Hero 标题：`clamp(38px, 6.5vw, 72px)`，移动端 600px 以下为 `32px`。
- 标签类文字通常为 `11px` 到 `13px`，大写标签使用 `.04em` 到 `.06em` 字距。

### 4.3 布局与组件规则

- 主容器最大宽度 `1280px`，左右内边距 `24px`。
- 导航高度 `64px`，纸色半透明 sticky 顶栏，滚动后增加阴影。
- 首页 Hero 使用深墨色背景、金色强调、噪声纹理、32px 点阵背景、居中搜索框和统计栏。
- 院校库桌面端使用 `260px 1fr` 主体网格，左侧筛选栏 sticky，顶部偏移 `80px`。
- 院校卡片为横向布局，图片区约 `200px`，700px 以下转为纵向。
- 专业列表必须使用 7 列 CSS Grid；1180px 以下横向滚动，760px 以下转为块状字段。
- 专业详情弹窗桌面端居中，移动端贴底；最大宽度 `860px`。
- 费用估算弹窗最大宽度 `640px`，智能推荐弹窗最大宽度 `720px`，登录弹窗最大宽度 `440px`。
- 右下角浮动按钮固定在 `24px` 位置，列方向排列。
- 响应式断点至少覆盖 `1180px`、`900px`、`768px`、`760px`、`700px`、`600px`。
- 关键动画为 `pulse`、`fadeDown`、`fadeUp`、`fadeIn`、`slideUp`。
