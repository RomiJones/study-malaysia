## 2. 结论摘要

静态 HTML 是一个完整的 StudyMY 用户端原型，包含首页、院校库、院校详情、专业列表、专业详情弹窗、搜索建议、筛选、收藏、院校对比、申请规划、费用估算、智能推荐、登录注册、会员中心、浮动工具按钮和响应式布局。后续用户端页面必须以该静态 HTML 为视觉和交互基准，实现 1:1 一致。

旧系统已经具备 Vue 3 用户端、NestJS 后端、TypeORM 数据模型、Pinia 状态、收藏、规划、推荐、申请管理和 Element Plus 管理端雏形，但当前字段、数据规模、页面样式和 UM 官方专业明细远未覆盖静态 HTML。后续升级需要先补齐后端数据模型与管理端维护能力，再进行用户端 1:1 还原。

Notion 是中文项目文档和任务管理来源，不是业务数据库；运行时业务数据必须进入 MySQL/API/前端状态体系，不得把 Notion 当作业务数据存储。

## 4. 用户端页面结构

### 4.1 全局导航

导航栏固定在顶部，带半透明纸色背景、模糊效果和底部边线。导航包含：

- StudyMY 品牌标识、校徽样式图标和 `2026` 徽标。
- 院校库。
- 申请规划。
- 费用估算。
- 智能推荐。
- 收藏，带数量徽标。
- 对比，带数量徽标。
- 注册 / 登录或会员入口。
- 移动端菜单按钮预留。

导航交互要求：

- 当前页面导航项使用深色底和白字。
- 收藏与对比数量从用户状态中实时读取。
- 点击工具入口可直接打开对应弹窗，不离开当前页面。

### 4.2 首页 Hero

Hero 使用深色背景、金色强调、径向光效、噪声纹理、点阵背景和居中排版。内容包含：

- 顶部标签：`实时更新 · 2025/2026 学年数据`。
- 主标题：`找到最适合你的 马来西亚大学`，其中 `马来西亚大学` 使用金色斜体强调。
- 副标题：展示院校数、专业数和平台定位。
- 中央搜索框：支持院校、专业、城市搜索。
- 快捷专业标签：商科、IT、医学、工科、酒店。
- 统计栏：认证院校、专业项目、QS Top 500、MQA 官方认证。

### 4.3 搜索与搜索建议

搜索支持：

- 输入院校中文名、英文名、简称、城市。
- 输入专业中文名、英文名、专业类别。
- 搜索建议展示标题与副标题。
- 搜索命中词高亮。
- 回车触发搜索。
- `Escape` 关闭建议。
- 点击院校建议进入院校详情。
- 点击专业建议进入院校详情后自动打开专业弹窗。

### 4.4 首页筛选区

筛选区为左侧粘性卡片，包含折叠分组：

- 院校类型：公立大学、私立大学。
- 学历层次：本科、硕士、博士。
- QS 世界排名：不限、Top 100、Top 200、Top 300、Top 500、Top 800。
- 年学费预算：滑杆、金额展示、快速选择。
- 专业类别：动态读取所有专业类别。
- 特殊条件：支持免语言申请开关。

筛选区交互要求：

- 已选筛选在顶部显示数量。
- 已选筛选以标签形式展示，可单独移除。
- 支持清除全部。
- 分组展开/收起使用箭头旋转动画。
- 筛选后结果页码重置为第 1 页。

### 4.5 院校列表与院校卡片

院校列表使用横向卡片，一页 8 所，带分页。卡片包含：

- 院校封面图、图片叠层、QS 排名浮层。
- 院校 logo。
- 院校类型标签、公立/私立。
- MQA/官方核验标签。
- 城市、建校年份。
- 中文名、英文名。
- 简介，两行截断。
- 专业类别标签。
- 学历层次标签。
- 学费展示：UM 等官方档案院校显示 `按专业显示`，其他院校显示年学费起。
- 收藏按钮。
- 对比按钮。
- 查看详情按钮。

交互要求：

- 点击卡片主体进入院校详情。
- 收藏与对比按钮阻止卡片点击冒泡。
- 对比最多 4 所。
- 卡片 hover 上浮、阴影增强、图片轻微放大。
- 移动端卡片由横向变为纵向。

### 4.6 院校详情页

院校详情页顶部为深色详情 Hero，包含：

概览页包含：

- 院校亮点卡片。

申请信息页包含：

### 4.7 专业列表

院校详情按学历层级展示专业表格，字段包括：

- 专业名称：中文名与英文名。
- 学院。
- 学制。
- 官方学费。
- 学费状态：官方已核验、待官方确认、详情页查看说明。

### 4.8 专业详情弹窗

专业详情使用底部弹出式移动端弹窗、居中桌面弹窗。内容包含：

- 官方来源与核验状态：来源状态、核验日期、官方链接、开学备注、官方学费来源。

院校对比页面包含：

- 横向滚动支持。

申请规划包含 5 个标签页：

- 申请概览。
- 学生画像。
- 材料清单。
- 申请管理。
- 签证清单。

申请概览包含：

- 申请准备度。
- 材料完成数量。
- 目标层次。
- 年度预算。
- 智能匹配推荐。
- 推荐分层：冲刺、主申、保底。

学生画像字段：

- 申请层次：本科、硕士、博士。
- 目标专业类别。
- GPA，满分 4.0。
- 雅思成绩，0 表示暂无。
- 年度留学预算，人民币。
- 工作经验：0-1 年、1-3 年、3-5 年、5 年以上。

材料清单根据层级动态生成：

- 状态：已完成、准备中、待准备、待起草。

申请管理包含：

- 自动根据推荐生成申请组合。
- 每个任务包含学校、专业、成本、层级、阶段、进度。
- 进度条展示。

签证清单包含：

- 收到正式录取通知书。
- 缴纳入学押金。
- 准备签证申请材料。
- 完成签证申请并获批。
- 出发前准备就绪。

## 6. 视觉规范

### 6.1 全局视觉基准

用户端必须 1:1 对齐静态 HTML。后续 UI 任务的验收不能只看构建通过，必须在浏览器中与静态 HTML 截图对比。

全局变量：

- 主墨色：`#0C0E1A`
- 次级墨色：`#3A3D52`
- 弱文本：`#8A8EA8`
- 页面纸色：`#FAFAF8`
- 浅纸色：`#F2F2EE`
- 边框：`#E4E4DC`

## 7. 用户流程

### 7.1 搜索浏览流程

1. 用户进入首页。
2. 用户在 Hero 搜索框输入院校、专业或城市。
3. 系统展示搜索建议。
4. 用户点击院校建议进入院校详情，或点击专业建议进入院校详情并打开专业弹窗。
5. 用户也可直接点击搜索按钮，在院校列表中查看筛选结果。

### 7.2 筛选选校流程

1. 用户打开院校库。
2. 用户设置院校类型、学历层次、QS 排名、预算、专业类别、免语言等筛选。
3. 系统实时更新结果数量、活跃筛选标签和列表。
4. 用户查看院校卡片并进入详情。
5. 用户收藏院校或加入对比。

### 7.3 专业详情流程

1. 用户进入院校详情。
2. 用户切换本科/硕士/博士专业标签。
3. 用户点击专业行。
4. 系统打开专业详情弹窗。
5. 用户查看学费、开学、语言、入学要求、申请材料、职业方向和官方来源。
6. 用户收藏专业或加入申请规划。

### 7.4 申请规划流程

1. 用户进入申请规划。
2. 用户完善学生画像。
3. 系统计算准备度并生成推荐。
4. 用户查看冲刺、主申、保底建议。
5. 用户检查材料清单并更新状态。
6. 用户进入申请管理查看任务进度。
7. 用户进入签证清单更新行前状态。

### 7.5 登录持久化流程

1. 未登录用户可先使用本地收藏、对比和规划。
2. 用户点击登录/注册。
3. 系统完成账号登录。
4. 本地状态需要与服务端用户数据合并。
5. 登录后收藏、规划、申请任务和签证清单应服务端持久化。
