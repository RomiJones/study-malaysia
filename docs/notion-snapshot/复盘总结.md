# 复盘总结

## 2026-06-16 信息采集标准化流程复盘

### 核心结论

StudyMY 官方院校数据采集不能按“发现一个缺口、修一个缺口”的方式推进。正确流程必须在一开始就明确任务范围、官方来源层级、字段标准、批量审计方式和发布门禁；后续任何单点漏采都视为同层级同字段的覆盖率事故，而不是单个专业的数据修补。

执行目标不是“尽快填完一批数据”，而是一次性按标准采集、生成可审计候选、批量验证字段覆盖、再决定是否入库和发布。速度必须服从准确性、完整证据链和可复现门禁。

### 执行前运行契约

每次开始采集前必须先固定运行契约，缺一项不得开采：

- 院校官方身份、官方域名和任务来源。
- 采集范围：院校资料、专业资料或完整范围。
- 学历层级：本科、硕士、博士；默认一次只处理一个院校的一个层级，除非用户明确授权多层级。
- 申请人范围：国际学生或其它明确范围。
- 学年、招生季或明确的 current-as-of 日期。
- 授权级别：只采集候选，还是允许入库、发布、上线、全栈验收。
- 产物路径、验证命令、回滚目标和 Notion/本地中文记录更新方式。

### 标准采集顺序

1. 先读项目规则、中文任务页、中文 PRD 和技术设计，不使用 `task.json` 作为事实来源。
2. 先建立官方来源图：院校官网、层级目录、专业详情页、费用页、招生要求页、申请指南、招生手册 PDF、学院子站和官方附件。
3. 先锁定权威专业目录和官方数量，再进入字段采集。目录出现次数、唯一官方条目、规范项目数和公开项目数必须分开统计。
4. 每个专业必须打开可唯一对应的官方详情页或官方手册章节，不能只停留在目录行。
5. 对 tab、accordion、隐藏面板、JavaScript 渲染内容和 PDF 表格进行当前官方页面核验；Markdown reader、文本代理、旧缓存和搜索结果只作为传输层或发现层。
6. 每个来源只快照一次并记录最终 URL、来源角色、抓取时间、学年、状态、本地路径和 SHA-256。
7. 先生成 `level_manifest`、`source_cache_index`、`candidate_dataset` 和 `pre_import_gap_audit`，再讨论是否入库。
8. 所有例外进入 exception queue，并固化到构建器、解析器、字段映射、导入器或回归测试中，禁止手工修改生成 JSON 掩盖缺口。

### 字段采集标准

每个专业的公开展示字段必须有官方值、明确未公布状态或待复核状态：

- 官方英文名称、学院、校区、层级、模式、国际生资格。
- 学制、开学月份、申请时间或官方未公布状态。
- 学费金额、币种、口径、学年、费用状态和官方来源。
- 入学要求、CGPA/GPA、语言要求、申请材料和特殊条件。
- 概述、课程结构、课程清单、实习、项目、研究方向、专修方向。
- 就业方向、专业认证或官方未公布状态。
- 每个关键字段的 provenance：专业页、通用规则、官方费率、官方未公布或待确认。

语言、本地化和中文说明只能在官方身份与事实稳定后生成。StudyMY 中文文案不能冒充官方翻译，也不能改变官方事实含义。

### 防返工规则

任何用户指出“官网有值但项目缺失”时，必须立即升级为批量审计：

- 同院校、同学历层级、同字段。
- 同页面结构，例如详情页 tab、accordion、隐藏面板、PDF 表格或学院子站。
- 同来源类型，例如官方详情页、费用页、招生要求页、申请指南。
- 同导入路径，例如候选构建器、字段映射、导入器或前端展示 fallback。

修复完成前必须输出字段差异审计：检测记录数、官方有值记录数、修复前差异数、修复后实质剩余差异数、仅顺序差异数、传输不可达数和代表性样本。传输不可达只能记为 transport exception，不得当作官方未公布。

### 入库与发布标准

采集、入库、发布是三个不同阶段：

- `采集`、`统计`、`整理`、`核验`：只生成审计候选和 gap audit，不改数据库。
- `入库`、`写入`、`发布`、`上线`、`项目展示`、`全栈验收`：才允许执行备份、dry run、事务写入、API/UI 验证和发布门禁。
- 入库前必须有完整候选和 pre-import gap audit；用户明确接受剩余缺口后才可继续。
- 入库后必须有 post-import display audit，确认数据库、公开 API、列表页、详情页和汇总数量一致。
- 每次写入前必须有备份和回滚路径；多导入脚本会更新同一个院校 profile 时必须顺序执行。

### 验收门禁

完成不能只汇报“已完成”。必须同时报告：

- 任务范围、官方域名、学年或 current-as-of 日期。
- 各层级官方数量、规范数量、公开数量、待审核数量、国际生不可用数量。
- 来源快照与关键 SHA-256。
- 字段覆盖情况、缺失字段、传输异常和待复核例外。
- 学费口径：官方总额、官方费率、官方未公布、冲突或待确认。
- 候选审计、费用审计、交付 envelope 审计、数据库/API/UI 验证结果。
- 测试、构建、浏览器、控制台和四语展示结果。
- 发布决策、回滚路径、中文记录更新状态和真实 Notion 是否已同步。

商用发布必须通过仓库发布门禁，例如 USM 使用：

```bash
node scripts/verify-usm-commercial-release.mjs
```

通用候选和交付审计必须优先使用仓库脚本与 Skill 审计器：

```bash
python3 scripts/audit_records.py MANIFEST.json --profile candidate --expected-count N --official-domain example.edu.my --summary-only
python3 scripts/audit_total_tuition.py MANIFEST.json --summary-only
python3 scripts/audit_delivery.py DELIVERY.json --summary-only
```

### 不可接受的执行方式

- 未固定范围就开始采集。
- 只读目录行，不进入专业详情页和深层官方链接。
- 把缓存、Markdown reader 或搜索片段缺字段当作官方未公布。
- 发现单条缺失后只修单条，不做同层级同字段批量审计。
- 手工改生成 JSON，而不是修构建器、解析器、映射或导入器。
- 用估算、范围、换算、延期费用或非唯一费用填主学费字段。
- 用“以官方页面为准”替代官网已经公布的可结构化事实。
- 入库前没有候选审计，发布前没有 API/UI/测试/构建/浏览器门禁。
- 未说明 Notion 是否真实更新。
