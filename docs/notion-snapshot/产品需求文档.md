# 产品需求文档

## 需求背景

基于静态页面提取全部功能，并升级既有 StudyMY 系统，目标包含用户端、后端服务和管理端；新用户端页面样式必须与静态页面完全一致。

## 参考源

静态页面：D:\mydev\StudyMY_UM_v58_na_display_tidy.html
旧系统：D:\mydev\study-malaysia

## 总体目标

把静态 HTML 中已经验证过的用户端展示和交互，升级为由旧系统支撑的三端产品：用户端、后端服务和管理端。

## 用户端功能范围

- 首页 Hero、导航、搜索入口和视觉品牌表达。
- 院校展示、院校卡片、排名、标签、图片、简介和官方来源。
- 专业搜索、专业筛选、活跃筛选标签、筛选折叠组。
- 专业卡片、专业列表、专业详情弹窗。
- 学费、学制、入学要求、语言要求、申请材料、开学时间、职业方向展示。
- 收藏、对比、规划工具、费用计算、用户画像、申请任务分层。
- 登录弹窗、浮动按钮、响应式移动端布局。

## 后端服务范围

- 院校、专业、费用、要求、申请材料、官方来源等数据模型。
- 搜索、筛选、详情、对比、收藏、规划和申请任务相关 API。
- 用户会话、收藏、规划、申请记录的持久化策略。
- 管理端字段维护所需接口。

## 管理端范围

- 院校和专业字段维护。
- 多语言或中文展示字段维护。
- 费用、申请要求、材料、开学时间、官方来源维护。
- 用户申请、收藏、规划和跟进记录管理。
- 权限、菜单、配置和操作日志延续旧系统能力。

## 视觉要求

用户端新页面必须以静态 HTML 为视觉基准，在字体、颜色、间距、圆角、阴影、卡片、按钮、弹窗、筛选区、对比表格和响应式表现上保持一致。涉及 UI 的任务必须做浏览器验证。

## 验收标准

- 静态页面功能已完整转化为中文任务项。
- 任务拆分覆盖用户端、后端服务和管理端。
- 每个任务都有中文验收标准和测试计划。
- 页面还原任务明确要求与静态 HTML 视觉一致。
- 文档明确说明 Notion 只是中文项目文档工具，不是业务数据库。

- 用户端是否需要四语言展示，还是先保持中文/英文？
