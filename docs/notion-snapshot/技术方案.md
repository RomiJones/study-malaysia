# 技术方案

## 背景

本项目基于静态 HTML 和既有 StudyMY monorepo 升级。旧系统包含 apps/web 用户端、apps/api 后端服务、apps/admin 管理端和 packages/shared 共享类型。

## 参考源

静态页面：D:\mydev\StudyMY_UM_v58_na_display_tidy.html

## 架构概览

- 用户端：Vue 3 + Vite，负责 1:1 还原静态 HTML 的视觉和交互。
- 后端服务：NestJS + TypeORM + MySQL，负责数据模型、搜索筛选、收藏、规划、申请等 API。
- 管理端：Vue 3 + Vite + Element Plus，负责维护院校、专业、内容、申请和权限。
- 共享包：维护三端共用类型和枚举。

## 升级原则

- 先提取需求和视觉规范，再写代码。
- 先补后端数据能力和管理端维护能力，再做用户端完整还原。
- 用户端 UI 任务必须浏览器验证，并与静态页面对比。
- Notion 只管理中文项目文档，不承担业务运行时数据存储。

## 静态页面视觉还原基线

TASK-002 已形成独立中文视觉基线文档：`docs/prd/TASK-002-static-page-visual-baseline.md`。后续用户端 Vue 页面必须优先复用或等价实现该文档中提取的静态 HTML 样式，不得以旧系统当前用户端样式作为最终视觉标准。

关键基线如下：

- 全局 token 以静态页 `:root` 为准：主墨色 `#0C0E1A`、纸色 `#FAFAF8`、金色 `#C8A84B`、青绿 `#1B7A72`、红色 `#C43830`、蓝色 `#1E4FA3`、大圆角 `16px`、小圆角 `10px`。
- 字体以 `DM Sans` 和 `DM Serif Display` 为准，基础字号 `15px`、行高 `1.6`。
- 首页必须还原深墨色 Hero、金色强调、噪声纹理、点阵背景、居中搜索框和统计栏。
- 院校库必须还原 260px 左侧 sticky 筛选栏、折叠筛选组、预算滑杆、活跃筛选标签、横向院校卡片和分页。
- 院校详情必须还原深色详情 Hero、标签页、官方信息卡片、申请信息和专业列表。
- 专业列表必须使用静态页 7 列 CSS Grid，1180px 以下横向滚动，760px 以下转为块状字段。
- 专业详情、费用估算、智能推荐和登录必须按静态页弹窗规则实现：移动端贴底，桌面端居中。
- 响应式断点至少覆盖 1180px、900px、768px、760px、700px、600px。
- UI 验收必须保留静态 HTML 与 Vue 页面同视口截图对比，至少覆盖首页首屏、筛选列表、院校详情、专业列表、专业详情弹窗、对比、规划和登录弹窗。

## 数据模型方向

需要覆盖院校、专业、费用、学制、申请周期、入学要求、语言要求、申请材料、官方来源、标签、职业方向、收藏、对比、规划和申请任务。

- 旧系统 README 可能存在终端编码显示问题，修改前应确认源文件实际编码。

### TASK-096 数据模型和数据准备技术边界

- **技术目标**: 将学校、专业等业务数据的多语言入库前提收口到后端数据层，明确四语言字段承载、公开展示状态、官方来源状态、费用审计状态和静态 HTML 数据准备校验方式。
- **适用范围**: `packages/shared/src/i18n.ts` 的 `SUPPORTED_LOCALES`、`LocalizedText`、`LocalizedStringArray`，`apps/api/src/db/entities.ts` 的 `UniversityEntity` 与 `ProgramEntity`，`apps/api/src/db/static-html-catalog.ts`、`static-html-importer.ts`、`verify-static-html.ts`、`import-static-html.ts`，以及 `tests/api/static-html-importer.test.ts`、`tests/api/catalog-localization-service.test.ts`。
- **非适用范围**: 不在 TASK-096 中修改用户端页面和 CSS，不定义最终 API 响应契约，不新增管理端维护页面，不执行未确认环境的真实写库导入，不处理 Review issue 状态流转。
- **关键检查**: 院校和专业主要展示字段必须能以 `en`、`ms`、`zh-CN`、`zh-TW` 结构存储；公开数据必须保留 `isPublished`、`publicDisplayStatus`、官方来源和费用审计字段；UM scope 校验必须稳定输出 1 所院校、248 个专业、239 个 ready 专业、240 个官方 MYR 学费、248 个官方费用来源和 245 个官方开学信息。
- **数据准备策略**: 静态 HTML 提取和导入必须支持 `--university-code UM` 或等价 scope；dry-run 优先，出现 code/slug 冲突或 scope 为空时阻塞；scope 导入默认不得 prune 非 UM 数据；正式导入后必须执行数据库统计校验。
- **多语言覆盖检查**: 后端目录数据需要专项覆盖率检查，识别 localized payload 形状错误、缺失 locale，以及英文或马来文字段中的中文内容；该检查是数据层质量门禁，不替代前端 i18n 审计。
- **验证命令**: `npm run check:static -- --input "D:\mydev\StudyMY_UM_v58_na_display_tidy.html" --layer base --university-code UM`、`npm run test -- tests/api/static-html-importer.test.ts tests/api/catalog-localization-service.test.ts`、`npm run test`、`npm run build`。

### TASK-099 多语言文案一致性技术边界

- **技术目标**: 将用户端多语言文案一致性作为独立质量门禁，覆盖 i18n key 完整性、可见硬编码文案扫描、脚本生成标签扫描、运行时动态文案 formatter、简繁转换和 raw API error 防直出。
- **适用范围**: `apps/web` 的 i18n messages、runtime text、locale transform、format helpers、用户可见错误提示、首页/院校/专业/规划等页面消费动态字段的显示路径，以及 `scripts/task040-i18n-audit.ts`、`scripts/task041-copy-audit.ts`、`tests/web/format.test.ts` 等专项验证。
- **非适用范围**: 不在 TASK-099 中设计数据库多语言字段、导入流程、后端 API 多语言契约、管理端维护入口或最终全页面视觉验收；这些内容分别由数据、后端、用户端页面和集成验证子任务处理。
- **关键检查**: `SUPPORTED_LOCALES` 必须保持 `en`、`ms`、`zh-CN`、`zh-TW`；四语言 messages leaf key 必须一致；英文和马来文 messages 不得含中文；马来文不得无意回退英文；繁体中文不得命中已知简体样本；Vue template 可见文字和 aria/placeholder/title/alt 文案不得绕过 i18n；用户端源码不得直接渲染 `error.message` 或 `err.message`。
- **动态数据策略**: 后端原始分类、院系、开学时间、学制、语言要求、官方备注和普通英文说明应先走统一 formatter；无法可靠本地化时，非对应语言界面使用当前语言的官方页面 fallback，不得直接透出不匹配语言的原始字符串。
- **Review 处理**: TASK-030-REV-005、TASK-030-REV-006、TASK-030-REV-007 属于 TASK-099 相关风险；当前专项脚本和 format 测试可作为复核依据，但真实 Review 状态更新应由 Review 流程完成。
- **验证命令**: `npm run verify:task041:i18n`、`npm run test -- tests/web/format.test.ts`；最终集成阶段仍需执行 `npm run test`、`npm run build` 和多语言浏览器验证。
